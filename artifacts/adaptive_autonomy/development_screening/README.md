# Development screening runner

Python standard library only. From this directory:

```text
python runner.py --dry-run --output dry_run_evidence
python -m unittest -v test_runner
```

To preserve a fresh failure-test audit, set `SCREENING_TEST_EVIDENCE` to an existing
new evidence directory before running tests. Its `failure_logging_evidence.json`
must not already exist. Normal test reruns do not change preserved evidence.

The output directory must not exist; reruns must use a new directory. Omitting
`--dry-run` still performs only a dry-run. There is no live CLI flag, provider SDK,
network code, credentials access, classifier, or adaptive reuse implementation.

`tasks.json` is generated by `runner.extract_tasks()` from the frozen task document
and checked against it on every load. Model messages contain only the prompt text.
All task IDs and hashes remain local. Source order and ten replicates are frozen.

`execute()` is the future provider integration seam, exercised solely by offline
fakes. It requires explicit authorization and configured provider/model/version.
It creates a fresh provider callable for each request. A future adapter must use
stateless requests with remote memory disabled and no hidden prompts or automatic
retries; provider-side behavior cannot be verified until that adapter is selected.
No live adapter or research model configuration has been chosen in this package.

Execution reserves output files exclusively, logs started and terminal attempt
events, retains semantic text unchanged, logs failures separately, and stops at
the first provider failure without retries. An empty reserved raw file on failure
is not a semantic response. The planned manifest is immutable; `attempts.jsonl`
records actual success/failure status and timestamps. A started event with no
terminal event indicates interruption and must be reviewed, not silently rerun.

The blank CSV includes all common rubric fields without coding any judgments.
Dry-run paths are plans, not responses. `dry_run_evidence` preserves validation,
inputs, schedule, offline test output and a simulated failure audit. No screening
results are claimed. Stop here pending independent review and explicit live-run
authorization.
